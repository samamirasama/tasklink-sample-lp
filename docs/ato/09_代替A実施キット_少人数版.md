# 代替A 実施キット（少人数版：ヒアリング＋Apple リマインダー運用を同じ2〜3人で連続実施）

- 作成日：2026年10月2日（金）
- 前提（ユーザー回答）：代替Aは実施可。ヒアリング体制は2〜3人。開発用Macなし。
- 位置づけ：10〜20人の計画（`03`、`05`）を、2〜3人で**開発ゼロ**のまま回せる形に縮めたもの。人数が少ないため、割合は出さず、1人ずつの事実を記録して「強い否定が出るか」「用途が絞れるか」を見る。

## 0. 全体の流れ（1人あたり約3週間）

| 週 | 工程 | 所要 | 使うもの |
|---|---|---|---|
| 0 | 事前ヒアリング（直近の保存行動） | 30〜40分 | `05_ヒアリング実施キット.md` 3章、`kit/interview_log.csv` |
| 0 | 設定を一緒に行う（リマインダーのリストと週1通知） | 10分 | 本書2章 |
| 1〜2 | ふだん通り使う。週1回の見返し | 日次1分、週1回5分 | `kit/altA_daily_log.csv`（毎日でなく、保存したときだけ記入でよい） |
| 2末 | 事後面談 | 20分 | 本書4章 |
| — | 判定 | — | 本書5章 |

2〜3人は**同時に**開始してよい。開始日と見返し曜日は人ごとに記録する。

## 1. 参加者の選び方（2〜3人で結果の意味を保つために）
- 必須：iPhone利用。直近30日に「保存したのに見返さなかった」具体例を1つ以上、事前ヒアリングで自力で挙げられる人。
- 避ける：企画者本人、企画を知っていて応援したい人（肯定に寄る）。**知人の紹介で集める場合は、直接の知人ではなく「知人の知人」を優先**し、企画の説明は募集文（`05` 1章）の範囲にとどめる。
- 可能なら1人は「SNS保存が多い人」、1人は「スクショが多い人」、1人は「Safariのリーディングリストやメモに溜める人」と、保存先が異なる人を選ぶ。用途の違いが見える。

## 2. 設定（参加者のiPhoneで、運営が一緒に行う。一工程ずつ）
1. 「リマインダー」アプリを開く。
2. 右下の「リストを追加」を押し、名前を「あとで」にして「完了」。
3. 「あとで」リストを開き、「＋ 新規」で「今週の見返し」という項目を作る。
4. その項目をタップ → 「i」マーク → 「日付」をオン → 「時刻」をオン → 曜日と時刻（例：日曜 20:00）を選ぶ → 「繰り返し」を「毎週」にする → 「完了」。
5. Safari で何かのページを開き、下の「共有」ボタン → 「リマインダー」を押す → リストが「あとで」になっていることを確認して「追加」。これで保存の練習は終わり。
6. Instagram での保存方法（投稿の紙飛行機マーク → 「共有先」→ 「リマインダー」）、X（共有 → 「他の方法で共有」→ 「リマインダー」）も1回ずつ練習する。
7. **日時は付けない**ことを伝える。「今週の見返し」以外の項目に日付を付けない。
8. iOS 26以降で Apple Intelligence が有効な端末では、共有時に「提案」が出ることがある。提案は使っても使わなくてもよい。使ったかどうかは事後面談で聞く。

## 3. 参加者への案内（そのまま渡す文）
> - SNSやWebで「あとで行きたい・買いたい・やりたい」と思ったものがあれば、共有ボタン → リマインダー → 「あとで」に入れてください。日付は付けないでください。
> - 日曜20時（設定した時刻）に「今週の見返し」の通知が来たら、「あとで」リストを開き、入っているものを1つずつ、「開く」「もう済んだので完了（丸を押す）」「まだ決めないのでそのまま」「もういらないので削除（左にスワイプ）」のどれかにしてください。全部やらなくて構いません。
> - 保存したとき、見返したときに、面倒だった点・迷った点があれば `altA_daily_log.csv` の該当欄に一言だけ書いてください。
> - 無理に件数を増やさないでください。ふだん通りで構いません。

## 5. 判定の目安（2〜3人用。割合ではなく、人ごとの事実で判断する）
| 観察 | 読み方 |
|---|---|
| 2週とも見返しを実施した人が1人もいない | **保留条件**。週次レビューの体験自体が成立していない。ATOを作っても同じ結果になる可能性が高い |
| 見返しは実施するが、削除・完了がほぼゼロで「そのまま」が溜まる | 「不要」操作の設計が鍵。ATOでは「不要」を肯定的に見せる設計の検証が最優先 |
| 保存が週1件未満の人が多数 | 困りごとの頻度が低い。対象者の条件を見直す |
| 保存先が1種類に集中（例：Instagramのみ） | **対象を絞る条件**。その導線に最適化したMVPへ |
| 「提案」で十分と答える人がいる | Apple リマインダーで足りる層。ATOの対象外として記録 |
| 全員が見返しを実施し、完了または削除が毎週発生 | 次の段階（ショートカット版試作、6章）へ進む材料になる |

## 6. 次段階：ショートカット版の試作（コード不要、Mac不要）
Apple リマインダー運用で「見返して手放す」行動が確認できた場合、**iOSの「ショートカット」アプリだけで**ATOの中核操作（共有→保存→週次に1件ずつ「開く／完了／保留／不要」）を再現する。開発環境もApple Developer Programも不要で、参加者のiPhoneにショートカットを共有（iCloudリンク）するだけで配布できる。

### 6.1 ショートカット1「あとでに入れる」（共有シート用）
1. ショートカットアプリ → 「＋」→ 名前を「あとでに入れる」。
2. 右上の「i」→ 「共有シートに表示」をオン → 受け取る種類を「URL」「テキスト」「イメージ」「Safariウェブページ」に限定。
3. アクション「共有シートから入力を受け取る」（自動で入る）。
4. アクション「新規リマインダーを追加」：タイトル＝入力（URLならそのURL。Safariウェブページなら「名前」を使う）、リスト＝「あとで」、メモ＝入力の種類と日時。日付は付けない。
5. アクション「通知を表示」：「保存しました」。
- 画像の場合：「イメージ」を受け取ったときは、アクション「写真アルバムに保存」でアルバム「あとで」に保存し、リマインダーには「画像（アルバム『あとで』）」と日時だけ書く。画像そのものはリマインダーに添付しない（添付アクションの有無は要確認）。

### 6.2 ショートカット2「今週の見返し」（週1回の自動実行）
1. 新規ショートカット「今週の見返し」。
2. アクション「リマインダーを検索」：リスト＝「あとで」、完了していない、作成日が古い順、上限5件。
3. アクション「各項目を繰り返す」。
4. 繰り返しの中：アクション「メニューから選択」：選択肢＝「開く」「完了」「保留」「不要」。プロンプトにリマインダーのタイトルを表示。
   - 「開く」：「URLを開く」（タイトルがURLの場合）。開いた後、もう一度同じメニューを出す。
   - 「完了」：「リマインダーを編集」で「完了済み」をオンにする（第三者ブログで「リマインダーを編集」に完了済みフィールドがあることを確認。実機でも1回確認する）。
   - 「保留」：何もしない。
   - 「不要」：「リマインダーを削除」（削除前に「確認を求める」を入れる）。
5. 繰り返しの外：アクション「テキストファイルに追加」で、日時・提示件数・各選択を1行ずつ `iCloud Drive/Shortcuts/ato_log.txt` に追記する（これが計測ログになる。本文やURLは書かない）。
6. 「オートメーション」タブ → 「＋」→ 「時刻」→ 曜日と時刻を設定 → 「すぐに実行」をオン → 実行するショートカットに「今週の見返し」を指定。

### 6.3 限界（正直に）
- ショートカットの実行は参加者のiPhone上で完結し、ログは本人が `ato_log.txt` を送ってくれた分だけ集まる。
- UIは簡素で、見返し画面の圧迫感・心地よさは本物のアプリと同じには測れない。「操作の流れが成立するか」「不要が使われるか」を見る用途に限る。
- 共有元によっては「Safariウェブページ」「URL」のどちらで渡るかが違う。1回目の保存で動かなければ、受け取る種類を増やして再試行する。
