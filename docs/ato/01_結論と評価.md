## 1. 結論（条件付き）

**判定：「対象・仕様を変えて、開発前の検証に進む」。開発GOではない。確度：中（技術面は高、需要・事業面は低）。**

理由の要約
- **技術的には作れる**（確度：高）。共有拡張で受け取り→共有コンテナに即保存→本体アプリで取得・整理、という構成はAppleの公式資料に沿う。端末内OCR（Vision）と端末内LLM（Foundation Models、無料。端末内は4,096トークン（公式ドキュメント、research/I）、画像入力可、iOS 27でPrivate Cloud Compute版32K）も確認できた。ただし共有拡張から本体を起動する公式手段はなく、バックグラウンド処理は即時性が保証されない。
- **事業として成立するかは未確認で、材料は厳しい**（確度：低）。無料の代替（Apple リマインダー、メモ、Google Keep、SNS内保存）が多く、月300円帯の既存製品（Raindrop Pro、Anybox、Bear Pro）は保存無制限・同期・検索を含む。あとで読む最大手だったPocketは利用者3,000万人超（報道）でも2025年7月に終了した。
- **差別化は「空白」として存在するが脆い**（確度：中）。「保存時に何も決めない」「未処理を少数ずつ自動で再提示」「完了・保留・不要で手放す」の3点セットを持つ製品は32件中で確認できなかった。ただし機能の組合せの空白にすぎず、Readwise（間隔反復）、Microsoft To Do（提案）、Pixel Screenshots（スクショのリマインド）など近接機能は複数あり、模倣は容易。
- **変動費は小さく、採算の鍵は需要と継続**（確度：中）。AI分類の原価は1件あたり約0.4〜1円（Claude Haiku 4.5／Sonnet 5.5、公式単価、1 USD＝157円の暫定換算）。問題は原価ではなく「払う人がいるか」。

変更すべき点（引継ぎ資料からの修正）
1. **スクリーンショット整理を中核にしない**。iOS（Visual Intelligence、写真の文字検索）とAndroid（Pixel Screenshots）がOS標準で進めている領域で、無料に勝てない。画像はURLと同じ「受け取れる1種類」にとどめる。
2. **狙う利用場面を「SNS・Webで見つけた、行動が必要なもの（行く・買う・やる）」に絞る**。「あとで読む記事」はInstapaper・Matter・Readwise・GoodLinksで飽和している。
3. **AI分類と5分類をMVPから外す**。手動の1タップ分類（または未分類のまま）で、分類自体が使われるかを先に見る。
4. **価格仮説（月300〜500円）は保留**。同価格帯の既存製品より機能量で劣るため、買い切り（GoodLinks ¥1,500、Anybox 買切¥6,000の例）も含めて試用後の実選択で決める。
5. **ローカル保存＋書き出しで開始し、アカウントは作らない**。Pocket・Omnivore終了への不信（突然の終了、データ消失）は乗り換え層の明確な不満であり、「終了しても手元に残る」設計が訴求点になり得る。App Store審査上もアカウント不要なら削除機能要件が発生しない（5.1.1(v)）。

## 4. 要点

### 4.1 技術的に作れることと、事業として成立することを分けた評価

| 観点 | 評価 | 根拠 | 確度 |
|---|---|---|---|
| 共有シートからURL・画像を受け取って永続保存 | 可能 | NSExtensionActivationRule でURL・画像・テキスト・ファイルを宣言可。App Groupの共有コンテナに保存（公式） | 高 |
| 共有拡張内で取得・AI処理を完了させる | 避けるべき | 「1秒未満で起動」「メモリ上限は前面アプリより大幅に低い」「システムが積極的に終了させる」（公式） | 高 |
| 保存直後に本体が自動で解析を続ける | 保証されない | BGTaskSchedulerは「システムが最適な時刻を決める」「数時間遅れうる」「アイドル時のみ」（公式）。共有拡張から本体を起動する公式手段なし（Appleエンジニア回答） | 高 |
| ユーザー操作で始めた処理をバックグラウンド継続 | 可能（iOS 26〜） | BGContinuedProcessingTask。ただし前面での明示操作が起点、拡張からは不可 | 高 |
| 端末内OCR | 可能 | Vision RecognizeTextRequest。日本語の明記は公式ページで確認できず（学習知識ではiOS 16以降対応）。実機確認が必要 | 中 |
| 端末内LLMで分類・タグ付け | 可能（条件付き） | Foundation Models の contentTagging ユースケース。4,096トークン上限、対応機種限定（iPhone 15 Pro／15 Pro Max、16以降、iPhone Air。公式対応表 support.apple.com/121115 をページ取得で確認） | 中 |
| 外部AI利用 | 可能（同意必須） | 審査ガイドライン5.1.2(i)：「サードパーティAIを含む第三者への共有は明示的に開示し、事前に明示的な許可を得る」（原文、ページ取得で確認） | 高 |
| ログイン必須ページ（Instagram等）の情報取得 | 困難 | LPMetadataProvider は匿名アクセス相当。ログイン壁では取得できない可能性が高い（推測、公式記述なし） | 中 |
| **需要（保存忘れで本当に困っているか）** | **未確認** | 不満の例はある（Safariリーディングリストが積み上がる、Xブックマークが貯まる、Instagram保存を忘れる）が、規模・深刻度は不明 | 低 |
| **乗り換え負担の受容** | **未確認** | SNS内保存は1タップ。共有シート経由は最低2〜3操作で、Raindrop・Instapaper・はてなでは共有拡張の不安定さが不満に挙がる | 低 |
| **課金理由** | **弱い** | 同価格帯の既存製品が機能量で上回る。Pocket終了は「保存行動の変化」が理由（Mozilla発表の要約） | 低 |

### 4.2 競合調査から分かったこと（要点）

1. **共有シート保存は標準装備**。保存専用12件中、確認できた範囲でほぼ全てが対応。ここで差はつかない。
2. **再提示の形は3種類あり、いずれも「未処理の保存物を自動で出す」ではない**。
   - 手動の日時リマインダー：Raindrop（Pro）、Fabric、Notion、Keep、タスク管理4件、Apple リマインダー
   - 間隔反復・ダイジェスト：Readwise（ハイライト）、Recall（要約、週次メール）
   - 提案型：Microsoft To Do（未完了を翌日提案）、Apple リマインダー（Siri提案）、Pixel Screenshots（スクショ単位の通知）
3. **「不要」を肯定的な操作として設計した製品は確認できなかった**。既存は削除・アーカイブ・保存解除。
4. **無料の最有力代替は Apple リマインダー**。共有シートからURL保存、日時・場所通知、無料。さらにiOS 26以降は、共有→リマインダーで**Apple Intelligenceが本文からリマインダー候補を提案し1タップで追加できる**（support.apple.com/124025の要約、research/H）。ATOとの差は「日時を決めなくても週次で再提示され、不要で手放せる」点だけであり、この差が利用者に価値として伝わるかが最大の検証点。
5. **スクショ領域はOSが取りに来ている**。Pixel Screenshots（端末内AI、リマインダー、コレクション、日本語対応、無料）はATOの企画に概念上最も近い。iOSもVisual Intelligenceでスクショからカレンダー追加・要約が可能（リマインダー作成は未確認）。
6. **終了リスクが乗り換え層の明確な不満**。Pocket（2025年）、Omnivore（2024年）、LINE Keep（2025年）、Raindropへの流入増（報道）。「ローカル保存・書き出し容易」は訴求点になり得る。
7. **価格帯**。月¥300前後（Raindrop Pro、Anybox、Bear Pro）、買い切り（GoodLinks ¥1,500、Anybox ¥6,000）、月¥1,000前後（Todoist、Matter、Readwise、Recall）。ATOの¥300〜500仮説は最下位帯と同じで、機能量で劣る。
8. **名称**。「Atode - Todoタスク管理」（無料、iOS）という既存アプリがあり、「ATO／あとで」はストア上で紛れやすい。候補「Yatta」にも「YATT」「Yata for GTD」「Yattask」の類似名がある（research/H）。商標・ストア名の再検討が必要。

### 4.3 狙う利用場面（1つ）と、無料手段から乗り換える理由

**利用場面**：「InstagramやX、Safariで見つけた『行きたい店・買いたい物・試したいこと』を、その場では何も決めずに共有シートでATOに送り、週に1回まとめて見返して、開く・完了・保留・不要のどれかを選ぶ」

**乗り換える理由（候補）と、その強さ**

| 既存の無料手段 | ATOが上回り得る点 | 強さ |
|---|---|---|
| Instagram保存・Xブックマーク・YouTube後で見る | 保存先が1か所になる。SNSを開かずに見返せる。SNS側に再提示・通知・書き出しがない（未確認含む） | 中。ただしSNS内保存の1タップには負けるため「全部移す」は無理。「行動が必要なものだけ」の併用が現実的 |
| Safariリーディングリスト | 「積み上がる」「未読が分かりにくい」の不満に対し、少数ずつ再提示して手放せる | 中 |
| Apple リマインダー | 日時を決めなくても週次で再提示される。決めなかったものが埋もれない。「不要」で手放せる | **弱**。リマインダーは共有保存・無料に加え、iOS 26でApple Intelligenceの候補提案も持つ（research/H）。差は体験の設計だけ |
| Apple メモ・Google Keep | 再提示がある。完了・不要で整理できる | 弱〜中 |

**正直な評価**：乗り換え理由は「弱〜中」。無料手段で「困っていない」人には届かない。ヒアリングで「忘れて困った具体例」を自力で挙げられる人に限定して検証する。

### 4.4 MVPに入れる機能・見送る機能

引継ぎ資料の候補を、調査結果で削減した。

| 判定 | 機能 | 理由 |
|---|---|---|
| **入れる（P0）** | 共有シートからURL・画像・テキストを受け取り、即保存して閉じる | 主入口。拡張は保存のみ（公式制約） |
| 入れる（P0） | 端末内に永続保存、一覧、詳細、元URL・元画像を開く | 分析失敗・通信断でも失わない |
| 入れる（P0） | 完了・保留（期限なし可）・不要と、取り消し | 差別化の核。「不要」を肯定的操作にする |
| 入れる（P0） | 週次レビュー画面（通知なしでも使える、少数提示） | 差別化の核。圧迫感を試用で測る |
| 入れる（P0） | 書き出し（JSON/CSV）と全削除 | 終了リスクへの不信に応える。審査要件 |
| 入れる（P0） | 共有元アプリ名・共有時のテキストの保存。タイトル未取得は「未取得」表示 | ログイン必須ページ対策。推測で埋めない |
| 入れる（P1） | 手動の簡易分類（行く／買う／やる の3種＋未分類）。自動分類なし | 5分類は多い。分類が使われるか自体を検証 |
| 入れる（P1） | 本体起動時のメタデータ取得（LinkPresentation）、取得元・取得時刻の保存 | 拡張内では行わない |
| 入れる（P1） | 任意の週次通知（既定オフ、曜日時刻指定） | 通知負担を測る |
| 入れる（P1） | タイトル・メモ・共有テキストの基本検索 | 低コスト |
| 条件付き（P2） | 端末内OCR（Vision）で画像の文字を検索対象に | 日本語精度を実機で確認してから |
| 条件付き（P2） | 端末内LLM（Foundation Models）による分類候補 | 手動分類の負担が試用で明確に出た場合のみ。端末内は4,096トークン（公式）・画像入力可だが、対応機種はiPhone 15 Pro以降に限定 |
| 見送り | 外部AI分類・要約 | 同意設計と費用の前に、分類の需要が未確認 |
| 見送り | 3分・10分・30分の時間別再提示 | 所要時間の推定根拠がない。誤りが不信を生む |
| 見送り | 同期・アカウント・クラウド保存 | 需要確認前の固定費・審査要件・終了リスクを避ける。機種変更は書き出し／読み込みで代替 |
| 見送り | スクショ自動取り込み | 「勝手に収集しない」方針。OS標準との競合 |
| 見送り（引継ぎどおり） | AIチャット、意味検索、位置情報通知、家族共有、PC版、Android版、価格追跡、SNS保存一覧の自動取得、カレンダー連携、大容量PDF・長尺動画 | 変更なし |

- 大量利用者（月300件超）に外部AIを無制限で付けると赤字になる。上限または端末内処理が必要。
- 事業の成否は「有料に転換する人数」と「継続率」で決まり、どちらも未検証。

## 5. リスク・注意点

### 5.1 事業・需要のリスク（技術では解けない）

| リスク | 内容 | 回避策 | 残る限界 |
|---|---|---|---|
| 困りごとの深刻度が低い | 「保存して忘れる」は自覚しても損失が小さく、行動を変えない可能性 | ヒアリングで「忘れて困った具体例」を必須条件に | 困っている人数と課金可能性は少人数調査では分からない |
| 乗り換え負担 | SNS内保存は1タップ。共有シート経由は2〜3操作で絶対に負ける | 「全部移す」ではなく「行動が必要なものだけ」と用途を限定 | SNS内の保存一覧はATOから見えず、分散は解消しない |
| 再提示が圧迫感になる | 未処理一覧は罪悪感を生む（タスク管理アプリの離脱理由と同型） | 少数提示、「不要」を肯定的に、通知は既定オフ、保留は無期限可 | 効果は試用でしか測れない |
| 差別化が脆い | 近接機能が多数あり、組合せの空白にすぎない | 差別化を機能でなく体験と「終了しても残る」設計に置く | 既存製品が同等機能を追加すれば消える |
| OS標準化 | Pixel Screenshots、iOS Visual Intelligence、Apple リマインダーの提案機能 | スクショ整理を中核にしない。URL＋行動管理に重心 | OS標準が「URLの再提示」まで進めば直接競合 |
| 課金理由が弱い | 同価格帯の製品が機能量で上回る | 無料で価値を確認し、課金は買い切りも含めて試用後に決める | 転換率は公開後の実測まで不明 |
| 名称 | 「Atode」等の既存アプリと紛れる | 名称・商標・ストア名を再検討 | 商標調査は未実施 |

### 5.2 技術・UXのリスク（設計で回避できるもの）と実機確認項目

| リスク | 回避策 | 残る限界 | 実機で確かめる項目 |
|---|---|---|---|
| 共有拡張内で処理が終わらない・落ちる | 拡張は「受け取って保存して閉じる」だけ。取得・分類は本体で | 本体を開くまでタイトルなし表示が続く | 共有元別の受信データ型（public.url／plain-text／image）、URLがURL型かData型か、画像複数枚でのメモリ上限 |
| バックグラウンド処理が走らない | 本体起動時に未処理キューを処理。BGContinuedProcessingTaskはユーザー操作起点で使う | 保存直後の自動解析は約束できない | BGProcessingTaskの実遅延、再起動後のキュー復旧 |
| ログイン必須ページの情報が取れない | URL・共有元アプリ名・付随テキストを保存。「未取得」表示 | Instagram等はURL文字列だけになり判別しにくい | Instagram、X、TikTok、YouTube、Safariから共有時に渡る内容、LPMetadataProviderの戻り値 |
| 共有拡張から本体を起動できない | ローカル通知で誘導、または次回起動時に処理 | 公式制約。裏技は審査リスク | 拡張からの通知が届くか、権限の反映 |
| 端末内OCR・LLMの日本語精度 | 取得値・推定値・不明を区別して表示。修正1タップ | 精度が低いと手動と変わらない | supportedRecognitionLanguagesに ja が含まれるか、SNSスクショでの精度、Foundation Modelsの availability と日本語タグ品質、4,096トークンで入る本文量 |
| 画像の容量 | 縮小保存を既定に | 原寸を求める人には不向き | 100件・1,000件時のアプリ容量 |
| プライバシー | 外部AIは明示同意、項目単位で送信対象を表示。同意なしでも保存・レビュー可 | 外部事業者の保存条件は規約依存 | 同意画面の文言と審査可否 |
| 通知が届かない・拒否 | 通知なしで週次レビューが完結 | 通知拒否者の再訪は記憶頼み | 通知許可率、無効化のタイミング |
| データ消失・機種変更 | ローカル＋書き出し／読み込み | 同期なしだと手動復元 | 書き出し・読み込みの実機動作 |
| サーバーでURL取得する場合 | プライベートIP拒否、リダイレクト再検証、サイズ・時間上限、ページ内指示を命令と扱わない。APIキーはアプリに置かない | 端末内取得なら不要だが通信・電池は端末負担 | 端末内取得とサーバー取得の比較 |
| 日本の手数料率 | App Store Connectで適用料率を確認 | 自動適用か不明 | 契約画面で確認 |

## 6. 代替案・改善案

1. **推奨：対象を絞って検証に進む**（本書の判定）。利用場面を「行動が必要な保存物」に限定し、AIなし・ローカル保存・アカウントなしの試作品で、共有→週次レビュー→完了/保留/不要の体験だけを確かめる。
2. **代替A：Apple リマインダー＋ショートカットで「疑似ATO」を先に試す**。共有シートからリマインダーの専用リストに保存し、週1回の通知でリストを見返す運用を、ヒアリング対象者に2週間やってもらう。これで「週次に見返して手放す」体験に価値があるかを、**開発ゼロで**確かめられる。価値が出なければATOを作っても出ない可能性が高い。
3. **代替B：買い切りの小さなユーティリティとして出す**。GoodLinks・Anyboxの例のように、¥1,000〜1,500の買い切りなら変動費ゼロ（AIなし）で、継続課金の説得が不要。ただし売上の上限は低い。
4. **保留**：ヒアリングで「困った具体例」が出ない、または代替Aで見返し行動が続かない場合は、企画を変更する。

## 7. 判断条件（開発へ進む／対象を絞る／保留）

閾値は仮置き。試用開始前に関係者で固定し、結果を見て変えない。未検証の数値を市場標準として扱わない。

**開発へ進む条件（すべて満たす）**
1. ヒアリング対象の過半数が、直近30日の「忘れて困った具体例」を自力で挙げられる。
2. 試用者の過半数が、開始7日後にも保存またはレビュー操作をしている。
3. 「完了」または「不要」で手放す操作が、初週より減らずに続く。
4. 通知を有効にした人の多数が、試用期間中に無効化していない。
5. 共有元上位3つ（想定：Safari、Instagram、X）で保存成功率が実用水準にあり、失敗原因が特定できている。
6. 試用後の価格選択で、数名が有料（買い切りまたは月額）を**実際に選ぶ**。口頭の意思は数えない。

**対象を絞る条件**
- 困りごとが特定の種類（店・場所、買い物）に集中 → その種類に限定。
- 共有元が1つに集中 → その導線に最適化。
- レビューは使われるが通知は嫌われる → 通知なし前提に変更。

**保留条件（いずれか）**
- 「困った具体例」が出ない人が多数。
- 共有操作の負担で初週に保存をやめる人が多数。
- 再提示が圧迫感として語られ、「不要」も使われない。
- 代替A（リマインダー運用）で十分と結論づける人が多数。
