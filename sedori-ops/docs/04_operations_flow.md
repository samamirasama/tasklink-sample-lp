# 業務フロー（仕入れ → 出品 → 販売 → 対応）

凡例: 【人】事業主が実行、【D】director、【R】researcher、【W】copywriter、【T】trader、【C】communicator

## 0. 前提

- 資金・許認可・アカウントは `routines/onboarding_checklist.md` を完了していること。
- 記録先は `data/*.csv`。ID体系は `06_data_schema.md`。

## 1. リサーチ（週2〜3回、または仕入れ先セール時）

1. 【人】対象（カテゴリ、仕入れ先、セール名）を `/sedori-research` に渡す。
2. 【R】候補抽出 → 利益試算 → スコアリング → `candidates.csv` 追記 → レポート。
3. 【D】コンプライアンス B1〜B8 と資金ゲートを判定。`decision` を `approved_for_purchase` / `hold` / `rejected` に更新。
4. 【人】承認済み候補を確認し、仕入れ可否を最終判断。

## 2. 仕入れ

1. 【人】仕入れ先で発注・支払い。請求書/領収書をPDF保存（ファイル名 `YYYYMMDD_仕入れ先_注文番号.pdf`）。
2. 【T】`purchases.csv` に記録（数量、単価、送料、請求書パス）。`candidates.csv` の `status` を `purchased` に。
3. 【T】資金残高を更新し、`capital.reserve_ratio` を下回っていないか確認。

## 3. 入荷・検品・出品準備

1. 【人】入荷検品（外箱破損、数量、型番一致）。不備があれば【C】が仕入れ先への連絡文面を作成。
2. 【W】出品文面を作成（`/sedori-listing <candidate_id>`）。禁止表現チェック → 【D】確認。
3. 【人】Amazon: 出品登録・FBA納品プラン作成・ラベル貼付・発送。ヤフオク!/メルカリShops: 出品確定。
4. 【T】`inventory.csv` に登録（SKU、FNSKU、数量、状態 `inbound` → 受領後 `in_stock`）。

## 4. 販売中

1. 【T】日次で価格を確認し、改定案を提示（下限価格 = 粗利率が `gross_margin_min` を割らない価格。それ以下には下げない）。
2. 【人】価格改定を反映（自動価格改定ツールを使う場合はプラットフォーム公式または規約準拠のものに限る）。
3. 【T】売上を `sales.csv` に記録（FBAレポートから転記）。
4. 【T】在庫の滞留（`sell_through_days_max` 超過）を検知したら、値下げ・返送・他販路の3案を提示。

## 5. 購入者対応

1. 【C】受信メッセージを分類（配送、商品状態、返品、キャンセル、その他）。
2. 【C】テンプレ（`templates/messages/`）をもとに返信文面を作成。SLA `response_sla_hours` 内。
3. 【C】`escalate_to_owner_when` に該当すれば事業主にエスカレーション。それ以外は事業主が確認して送信。
4. 【C】`contacts.csv` に記録。

## 6. 返品・返金

1. 【人】プラットフォームの規定に従って処理。
2. 【T】`sales.csv` に返品を記録し、粗利を再計算。返品率が `return_rate_assumed` を超えたら要因分析。

## 7. 月次締め

1. 【T】`scripts/kpi_report.py` で売上・粗利・ROI・回転・返品率を集計。
2. 【D】目標との差分、規約・手数料の変更、次月の資金配分案をまとめる。
3. 【人】税務用に売上・仕入れ・経費を会計ソフトへ。

## 8. 例外処理

| 事象 | 一次対応 |
|---|---|
| Amazonから真贋調査・出品停止の通知 | 【D】即エスカレーション。【T】該当SKUの請求書を揃える。【C】POA（改善計画）の下書き |
| 仕入れ先からキャンセル・数量制限通知 | 【T】`purchases.csv` 更新。【R】代替仕入れ先を再調査 |
| 値崩れ（出品者急増） | 【T】損切り価格（粗利ゼロ）と保持の期待値を比較して提示 |
| 低評価・クレーム | 【C】一次返信。2往復目以降はエスカレーション |
